

> 目标：替代华为系统自带的录音转文本功能，通过自建 ASR（whisper.cpp）+ 大模型文本后处理，降低成本

---

## 一、整体架构

```
录音采集（手机端）
      │
      ▼
上传音频文件
      │
      ▼
Go 后端服务（任务队列，串行处理）
      │
      ├─→ ffmpeg 转码为 16kHz 单声道 wav
      │
      ▼
whisper.cpp Server（本地 ASR，转写为文字）
      │
      ▼
（可选）文本 LLM 润色/纠错/加标点
      │
      ▼
结果存库（MongoDB/MySQL）+ 回传展示
```

**核心思路**：ASR（语音转文字）和 LLM 文本理解是两个成本量级不同的环节，分开处理比直接调用大模型的语音接口便宜很多。ASR 自建部署，只有服务器成本，没有按次计费。

---

## 二、技术选型

|环节|方案|说明|
|---|---|---|
|客户端采集|Android 原生 App（Kotlin）或系统录音+自动化脚本|手机系统为 HarmonyOS 4.3（兼容 Android），可直接装 APK|
|ASR 引擎|whisper.cpp（本地部署，量化模型）|中文效果可用，CPU 可跑，无按次费用|
|后端服务|Go|与现有技术栈一致，负责任务队列、转码调度、结果存储|
|文本后处理（可选）|文本类 LLM API|加标点、纠错、摘要，按 token 计费，成本低|
|存储|MongoDB / MySQL|沿用现有基础设施|

## 三、服务器硬件评估

服务器配置：**2 核 2G**

### 各模型量化后内存占用参考

|模型|参数量|Q5_0 量化后大小|实际运行内存占用|
|---|---|---|---|
|tiny|39M|~30MB|~150-200MB|
|base|74M|~55MB|~200-300MB|
|**small**|244M|~180MB|**~500-700MB**（推荐档位）|
|medium|769M|~530MB|~1.2-1.5GB（勉强可跑，风险较高）|
|large-v3|1.5B|~1GB|~2.5-3GB+（不建议）|

### 结论

- 推荐使用 **small 模型 + Q5_0 量化**，2G 内存留有余地
- 不追求实时可用异步队列处理，medium 模型也可考虑，但需加 swap 防 OOM
- 如对准确率要求高，可采用**混合方案**：本地 whisper.cpp 处理低频/不敏感内容，正式场景走云厂商 ASR API（阿里云/腾讯云/讯飞，按分钟计费，比调用大模型语音接口便宜）
- 2核机器不支持并发转写，必须做**串行任务队列**

## 四、服务器部署方案（CentOS 7）

### 4.1 CentOS 7 仓库修复（前置步骤）

CentOS 7 官方源已 EOL，`mirrorlist.centos.org` 不可用，需指向 vault 或国内镜像：

```bash
# 使用阿里云 vault 镜像（推荐，国内访问快）
sudo curl -o /etc/yum.repos.d/CentOS-Base.repo https://mirrors.aliyun.com/repo/Centos-vault-7.9.2009.repo
sudo yum clean all
sudo yum makecache
```

> **注意**：SCL 仓库（`CentOS-SCLo-scl.repo`）走 devtoolset 这条路在 CentOS 7 EOL 后经常出现 `Cannot find a valid baseurl` 等问题，反复排查成本高，**不建议继续深挖，直接使用下方 conda 方案获取新版 gcc**。

### 4.2 用 conda 获取新版 gcc/cmake（跳过 SCL/devtoolset）

whisper.cpp 需要支持 C++17 的编译器，CentOS 7 自带 gcc 4.8.5 版本太老，用 conda 装新版最省心：

```bash
# 下载 miniforge（清华源）
wget https://mirrors.tuna.tsinghua.edu.cn/github-release/conda-forge/miniforge/LatestRelease/Miniforge3-Linux-x86_64.sh

bash Miniforge3-Linux-x86_64.sh -b -p /opt/miniforge3
source /opt/miniforge3/bin/activate

# 换清华镜像加速
conda config --add channels https://mirrors.tuna.tsinghua.edu.cn/anaconda/cloud/conda-forge/
conda config --set show_channel_urls yes

# 安装新版 gcc/g++/cmake
conda install -y gcc=11 gxx=11 cmake

# 验证
gcc --version
cmake --version
```

> 每次重新登录服务器编译前，需要先 `source /opt/miniforge3/bin/activate` 激活环境。

### 4.3 安装 ffmpeg

CentOS 默认源没有 ffmpeg，国内服务器建议用静态编译二进制，避免依赖问题：

```bash
wget https://johnvansickle.com/ffmpeg/releases/ffmpeg-release-amd64-static.tar.xz
tar -xf ffmpeg-release-amd64-static.tar.xz
sudo cp ffmpeg-*-amd64-static/ffmpeg /usr/local/bin/
sudo cp ffmpeg-*-amd64-static/ffprobe /usr/local/bin/
ffmpeg -version
```

### 4.4 编译 whisper.cpp

```bash
git clone https://github.com/ggerganov/whisper.cpp.git
cd whisper.cpp

# 确认CPU指令集支持
cat /proc/cpuinfo | grep avx2

cmake -B build -DGGML_AVX2=ON -DCMAKE_BUILD_TYPE=Release
cmake --build build -j2 --config Release
```

若需显式指定 conda 编译器（`ls /opt/miniforge3/bin/ | grep gcc` 确认实际文件名后再填）：

```bash
cmake -B build \
  -DCMAKE_C_COMPILER=/opt/miniforge3/bin/x86_64-conda-linux-gnu-gcc \
  -DCMAKE_CXX_COMPILER=/opt/miniforge3/bin/x86_64-conda-linux-gnu-g++ \
  -DGGML_AVX2=ON \
  -DCMAKE_BUILD_TYPE=Release

cmake --build build -j2 --config Release
```

### 4.7 部署为常驻服务（whisper-server + systemd）

```bash
./build/bin/whisper-server \
  -m ./models/ggml-small-q5_0.bin \
  -l zh \
  --host 0.0.0.0 \
  --port 8081 \
  -t 2
```

`systemd` 配置（`/etc/systemd/system/whisper-server.service`）：

```ini
[Unit]
Description=Whisper.cpp ASR Server
After=network.target

[Service]
Type=simple
WorkingDirectory=/root/whisper.cpp
ExecStart=/root/whisper.cpp/build/bin/whisper-server -m /root/whisper.cpp/models/ggml-small-q5_0.bin -l zh --host 0.0.0.0 --port 8081 -t 2
Restart=on-failure
RestartSec=5
MemoryMax=1400M

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable whisper-server
sudo systemctl start whisper-server
sudo systemctl status whisper-server
```

`MemoryMax=1400M` 做内存硬限制，超限由 cgroup 杀掉重启，比整机 OOM 更可控。

### 4.8 其他注意事项

- **防火墙**：若 `--host 127.0.0.1`（仅本机）通常无需开放端口；若 `--host 0.0.0.0`（联调外网访问）需开放 `8081/tcp`
- **SELinux**：如遇权限相关诡异报错，`getenforce` 检查状态，排查用可临时 `sudo setenforce 0`，生产环境建议后续配置正确策略而非长期关闭
- **长期建议**：CentOS 7 已 EOL，若是新服务器，建议直接换成 Rocky Linux / AlmaLinux 或 CentOS Stream 9，避免后续持续踩仓库坑

## 五、Go 后端开发方案

### 5.1 调用 whisper-server 接口

```go
package main

import (
	"bytes"
	"encoding/json"
	"fmt"
	"io"
	"mime/multipart"
	"net/http"
	"os"
	"os/exec"
	"time"
)

type WhisperResponse struct {
	Text string `json:"text"`
}

func TranscribeAudio(filePath string) (string, error) {
	// 建议 Go 服务和 whisper-server 同机部署时始终走 127.0.0.1；
	// 即使联调阶段 whisper-server 暂时监听 0.0.0.0，也不建议后端走公网 IP。
	whisperURL := os.Getenv("WHISPER_SERVER_URL")
	if whisperURL == "" {
		whisperURL = "http://127.0.0.1:8081"
	}

	file, err := os.Open(filePath)
	if err != nil {
		return "", fmt.Errorf("打开文件失败: %w", err)
	}
	defer file.Close()

	body := &bytes.Buffer{}
	writer := multipart.NewWriter(body)

	part, err := writer.CreateFormFile("file", filePath)
	if err != nil {
		return "", err
	}
	if _, err := io.Copy(part, file); err != nil {
		return "", err
	}

	writer.WriteField("temperature", "0.0")
	writer.WriteField("response_format", "json")

	if err := writer.Close(); err != nil {
		return "", err
	}

	req, err := http.NewRequest("POST", whisperURL+"/inference", body)
	if err != nil {
		return "", err
	}
	req.Header.Set("Content-Type", writer.FormDataContentType())

	client := &http.Client{Timeout: 10 * time.Minute}
	resp, err := client.Do(req)
	if err != nil {
		return "", fmt.Errorf("请求whisper-server失败: %w", err)
	}
	defer resp.Body.Close()

	respBody, err := io.ReadAll(resp.Body)
	if err != nil {
		return "", err
	}

	if resp.StatusCode != http.StatusOK {
		return "", fmt.Errorf("whisper-server返回错误: %s", string(respBody))
	}

	var result WhisperResponse
	if err := json.Unmarshal(respBody, &result); err != nil {
		return "", fmt.Errorf("解析响应失败: %w", err)
	}

	return result.Text, nil
}
```

### 5.2 音频转码（调用 ffmpeg）

```go
func ConvertToWav(inputPath, outputPath string) error {
	cmd := exec.Command("ffmpeg", "-y", "-i", inputPath,
		"-ar", "16000", "-ac", "1", "-c:a", "pcm_s16le", outputPath)
	return cmd.Run()
}
```

### 5.3 串行任务队列（2核机器不支持并发转写）

```go
var transcribeQueue = make(chan string, 100) // 存文件路径

func init() {
	go func() {
		for filePath := range transcribeQueue {
			// 先转码，再推理，和第十节状态机保持一致
			wavPath := filePath + ".16k.wav"
			if err := ConvertToWav(filePath, wavPath); err != nil {
				log.Printf("转码失败: %v", err)
				continue
			}

			text, err := TranscribeAudio(wavPath)
			if err != nil {
				log.Printf("转写失败: %v", err)
				continue
			}
			saveResult(filePath, text)
			_ = os.Remove(wavPath)
		}
	}()
}
```

## 六、客户端开发方向（Flutter）

手机系统 HarmonyOS 4.3.0.206，兼容 Android 生态，可直接装 Flutter 打出的 APK。可复用现有 Jenkins + Docker CI/CD 流程出包。

### 6.1 技术选型

|功能|库|说明|
|---|---|---|
|录音|`record`|支持直接指定采样率/声道，可录成 16kHz 单声道，省去后端 ffmpeg 转码|
|权限|`permission_handler`|申请 `RECORD_AUDIO`|
|上传|`dio`|multipart 上传，拦截器处理重试/断点续传|
|后台录音（可选）|`flutter_foreground_task` 或同类包|需要切后台不中断录音时才用，否则前台足够|
|本地状态/历史|`provider` / `riverpod` + `sqflite`|转写历史本地缓存，避免重复请求后端|

### 6.2 录音示例

```dart
import 'package:record/record.dart';

final record = AudioRecorder();

Future<void> startRecording() async {
  if (await record.hasPermission()) {
    final path = '/storage/emulated/0/Download/rec_${DateTime.now().millisecondsSinceEpoch}.wav';

      ),
      path: path,
    );
  }
}

  return await record.stop(); // 返回文件路径

```

### 6.3 上传示例

```dart
import 'package:dio/dio.dart';

Future<String> uploadAndTranscribe(String filePath) async {
  final dio = Dio();
  final formData = FormData.fromMap({
    'file': await MultipartFile.fromFile(filePath, filename: 'audio.wav'),
    'lang': 'zh',
    'need_polish': false,
  });

  // 第十节定义为异步任务：先拿 task_id，再轮询状态
  final createResp = await dio.post(
    'https://your-server.com/api/transcribe',
    data: formData,
  );

  final taskId = createResp.data['data']['task_id'] as String;

  while (true) {
    await Future.delayed(const Duration(seconds: 2));
    final statusResp = await dio.get('https://your-server.com/api/transcribe/$taskId');
    final data = statusResp.data['data'];
    final status = data['status'] as String;
    if (status == 'success') return data['text'] as String;
    if (status == 'failed') throw Exception(data['error_msg'] ?? 'transcribe failed');
  }
}
```

### 6.4 通话录音场景

如果需要录通话而非仅录音笔记，华为对通话录音 API 限制较多，可能需无障碍服务或第三方录音方案，建议先评估该场景是否是硬需求，非硬需求可先不做。

### 6.5 录音文件如何进入 App（两种方式）

系统录音机是封闭 App，无法把转写逻辑嵌进去，文件必须从录音机"出来"之后再被自己的 App 处理，有两种可行方式：

**方式一：分享（Share Intent）—— 推荐先做这个**

用户录完音后，在系统录音机里点分享，选择自己的 App，文件通过 Android 标准分享机制传入，App 收到后自动上传转写。

- 优点：实现简单，不需要额外权限，稳定
- 缺点：每次需要手动点分享，非全自动

```dart
import 'package:receive_sharing_intent/receive_sharing_intent.dart';

void listenForSharedFiles() {
  ReceiveSharingIntent.getMediaStream().listen((files) {
    if (files.isNotEmpty) {
      uploadAndTranscribe(files.first.path);
    }
  });

  // 冷启动（App未打开，直接分享唤起）也要处理
  ReceiveSharingIntent.getInitialMedia().then((files) {
    if (files.isNotEmpty) {
      uploadAndTranscribe(files.first.path);
    }
  });
}
```

**方式二：后台监听录音文件夹（全自动，后续再评估）**

App 后台监听存储目录，检测到新文件自动触发上传，无需手动分享。

- 优点：全自动，用户无感
- 缺点：
    - 需要 `MANAGE_EXTERNAL_STORAGE` 权限（Android 11+），需引导用户单独授权
    - 华为电池管理对后台常驻进程限制较严，监听服务可能被杀，需额外处理自启动白名单/省电豁免，稳定性弱于方式一
    - 通话录音具体存储路径需在目标机型上实测确认（不同 HarmonyOS 版本/是否装第三方录音软件，路径可能不同）

```dart
import 'package:watcher/watcher.dart';

void watchRecordingFolder(String folderPath) {
  final watcher = DirectoryWatcher(folderPath);
  watcher.events.listen((event) {
    if (event.type == ChangeType.ADD && event.path.endsWith('.wav')) {
      uploadAndTranscribe(event.path);
    }
  });
}
```

**建议**：先做方式一跑通整体流程，验证转写效果和后端稳定性后，再评估是否投入精力做方式二（涉及权限引导、电池策略豁免等额外工作量）。

## 七、落地节奏建议

1. 服务器上先把 whisper.cpp 跑通（编译 + 量化 + 测试转写），用真实中文录音验证准确率与耗时

## 九、验收标准（建议补充为里程碑门槛）

### 9.1 功能验收（必须满足）

- 可上传常见音频格式：`wav/mp3/m4a/aac`
- 后端可自动转码为 `16kHz/mono/wav` 并完成转写
- 返回文本可被前端正确展示并可查询历史
- 单任务失败不影响后续任务消费（队列不中断）

### 9.2 性能验收（2核2G基线）

- 5 分钟中文普通话录音，端到端（上传完成到返回文本）P95 小于 120 秒
- whisper-server 稳态内存低于 1.4GB（以进程 RSS 实测为准）
- 连续处理 50 条 1~5 分钟任务不出现进程退出或服务不可用

### 9.3 准确率验收（先用业务可接受口径）

- 抽样 30 条真实中文录音（含口音/环境噪声），人工主观评分达到“可读可用”
- 关键业务关键词（人名/地名/术语）识别错误率可被接受；不达标时再评估：
  - 更换模型档位（small -> medium）
  - 增加术语后处理词典
  - 混合云 ASR 兜底

## 十、接口与任务状态设计（建议先定契约再开发）

### 10.1 API 草案

- `POST /api/transcribe`
  - 入参（multipart/form-data）：
    - `file`：必填，音频文件（支持 `wav/mp3/m4a/aac`）
    - `lang`：可选，默认 `zh`
    - `need_polish`：可选，默认 `false`
    - `client_trace_id`：可选，客户端幂等追踪 ID（建议 UUID）
  - 出参：`task_id`、`status`（`queued`）、`message`
- `GET /api/transcribe/{task_id}`
  - 出参：`status`（`queued|processing|success|failed`）、`text`、`error_code`、`error_msg`、`duration_ms`

`POST /api/transcribe` 成功响应示例：

```json
{
  "code": 0,
  "message": "accepted",
  "data": {
    "task_id": "asr_20260918_000001",
    "status": "queued"
  },
  "request_id": "req_f0ab2d8f"
}
```

`GET /api/transcribe/{task_id}` 成功（处理中）响应示例：

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "task_id": "asr_20260918_000001",
    "status": "processing",
    "text": "",
    "error_code": "",
    "error_msg": "",
    "duration_ms": 0
  },
  "request_id": "req_17f3c9a2"
}
```

`GET /api/transcribe/{task_id}` 成功（完成）响应示例：

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "task_id": "asr_20260918_000001",
    "status": "success",
    "text": "今天下午两点开项目例会，地点在三号会议室。",
    "error_code": "",
    "error_msg": "",
    "duration_ms": 42351
  },
  "request_id": "req_3410a91c"
}
```

### 10.2 任务状态机

`queued -> processing -> success|failed`

- 上传成功即入队并落库状态 `queued`
- worker 消费前将状态改为 `processing`
- 完成后写 `success` + 文本；失败写 `failed` + 错误原因
- 客户端轮询查询状态，避免上传请求长连接等待

状态说明：

- `queued`：已接收，等待转码/转写
- `processing`：正在执行（转码或推理阶段）
- `success`：完成，可读取 `text`
- `failed`：失败，可读取 `error_code` 与 `error_msg`

建议轮询策略：

- 客户端上传成功后每 2 秒轮询一次
- 单任务轮询超时建议 10 分钟，超时后提示用户稍后重试
- 当状态为 `success` 或 `failed` 时停止轮询

### 10.3 最小数据表字段（MySQL/Mongo 通用思路）

- `task_id`
- `client_trace_id`
- `source_file_path`
- `source_format`
- `file_size_bytes`
- `audio_duration_sec`
- `status`
- `text`
- `need_polish`
- `lang`
- `started_at/finished_at`
- `duration_ms`
- `retry_count`
- `request_id`
- `deleted_at`（可选，软删除）
- `error_msg`
- `error_code`
- `created_at/updated_at`

### 10.4 错误码约定（最小集合）

- `0`：成功
- `40001`：参数错误（缺少文件/格式不支持）
- `40002`：文件过大（超服务限制）
- `40401`：任务不存在
- `42901`：系统繁忙（队列已满）
- `50001`：转码失败（ffmpeg 失败）
- `50002`：ASR 推理失败（whisper-server 失败）
- `50003`：结果落库失败
- `50004`：任务超时

统一错误响应示例：

```json
{
  "code": 50002,
  "message": "asr inference failed",
  "data": null,
  "request_id": "req_66f42de3"
}
```

### 10.5 服务端约束建议（防止接口漂移）

- 单文件大小限制：建议先定为 50MB（后续按资源调整）
- 音频时长限制：建议先定为 30 分钟
- 所有响应必须返回 `request_id`，便于日志追踪
- `task_id` 全局唯一且不可复用

## 十一、稳定性与运维补充

### 11.1 队列可靠性

- 当前内存 `chan` 方案适合 PoC，重启会丢任务
- 上线建议切 Redis/BullMQ 类持久队列，至少保证：
  - 服务重启后任务可恢复
  - 失败任务可重试（建议最多 2 次，指数退避）

### 11.2 超时与重试

- `ffmpeg` 转码超时：建议 2~5 分钟（按文件时长动态）
- whisper 推理超时：建议 5~10 分钟
- 超时后标记 `failed`，避免任务永久卡死

### 11.3 观测指标（最小集）

- 每分钟任务数、成功率、失败率
- 平均/P95 转写耗时
- 队列堆积长度
- whisper-server 进程内存与重启次数

### 11.4 日志与告警

- 任务维度日志必须带 `task_id`（方便排障串联）
- 连续失败率超过阈值（如 10 分钟 >20%）触发告警
- whisper-server 重启频繁时告警（提示模型档位或并发策略需调整）

## 十三、风险与回滚预案

- **风险1：准确率不达标**
  - 预案：先引入关键词词典后处理；再评估 medium；仍不达标则云 ASR 兜底
- **风险2：2核2G 下高峰堆积严重**
  - 预案：限制上传频率 + 排队提示；必要时升级到 4核8G
- **风险3：后台自动监听不稳定（被系统杀进程）**
  - 预案：第一阶段仅上线 Share Intent；后台监听列入二期
- **风险4：CentOS 7 生态老化**
  - 预案：当前按 conda 方案落地，后续迁移 Rocky/Alma 作为运维任务单独排期
